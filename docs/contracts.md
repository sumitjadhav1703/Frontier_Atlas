# Shared implementation contracts

## Canonical payload and Sheet projection

Preserve the field casing and nesting in the employer’s tables. Store typed JSON internally. Flatten nested keys to dot-separated Sheet headers, serialize authors as a JSON array, and keep numeric and Boolean cells typed. Every public row, including a mapping observation, has a legitimate source URL. Add fields below to preserve identity, auditability and full-text provenance. The News schema and extra evidence fields are project choices because the brief leaves them open.

| Tab and recordType | Required payload and counting rule | Durable identity |
| --- | --- | --- |
| Startups · STARTUP | schemaVersion="1.0", source.name, source.url, content.entityName, content.data.employeeCount (nonnegative integer if explicitly available), collectedAt as UTC ISO-8601. Ranges stay in raw evidence, optional count stays null. Explicit AI scope from category/tag or source description. | Verified organization ID + alias/source ID crosswalk. Different startups can share names or a hosting domain. |
| Products · PRODUCT | schemaVersion, source.name, source.url, content.startupName, content.pricingModel ∈ FREE/FREEMIUM/PAID/ENTERPRISE, collectedAt. Add content.productName, product URL, owner and pricing evidence URLs. Both owner and price must be evidenced to count. | Owner ID + product-specific stable ID or canonical product URL. Two products from one company count separately. Plan tiers, locales and relaunch URLs do not. |
| Research Papers · RESEARCH_PAPER | schemaVersion, content.title, content.authors[], content.paper_url, content.github_url, content.github_stars (nonnegative integer), content.published_date. Add source.name/url, collectedAt, repo ID, repo association evidence and starsObservedAt. Only complete paper–repo–metric joins count toward 1,000. Zero observed stars is valid. | Versionless arXiv ID, else validated DOI with same-work crosswalk. Keep version and all repo edges internally. One deterministic primary repo per paper in the Sheet. |
| Jobs · JOB | schemaVersion, content.company, content.date, content.is_remote, content.role_family. Add title, listing URL, original employer job URL, source.name/url, body provenance and collectedAt. Require a source-backed Boolean or quarantine for review. Controlled role families via versioned rules on evidenced role title/department. | Employer + requisition ID first, canonical original job URL second. Candidate matches with an ambiguous ID stay separate or pending review. |
| News · NEWS | schemaVersion, source.name/url, collectedAt, content.title, content.date, content.text (full body internally), content.article_url. Jobs also store full descriptions. Record original time value and extraction method. | Publisher article ID or canonical URL. Preserve alternate URLs. Treat a syndicated copy as the same only with verified original reference. |
| Entity Mapping Log | entityType, rawName, canonicalName (nullable on abstain), canonicalID, method, decision, evidenceURL, runID, ruleVersion. Keep an observation for new, unchanged, merged and unresolved names. | Idempotent observation key = source item + field + raw value + rule version. |

**Pricing policy.** Confirm who operates the named product from an official about, legal, vendor profile or attributed directory field. Permanent free and paid tiers together → FREEMIUM. Paid tier with only a temporary trial → PAID. Documented free-only offering → FREE. Enterprise-only offer with explicit enterprise terms → ENTERPRISE. Where multiple categories might apply, prefer FREEMIUM or PAID if a public self-service tier applies. Missing checkout, an open-source label or “contact us” alone supplies insufficient evidence. Never promote an employer, product or field merely because an LLM repeats its name.

## Evidence and publishing

Each accepted field stores a reference to a captured source observation: original/final URL, discovered ID, fetched_at UTC, status, parser version, response hash, and a field-specific JSON pointer or text span. Keep source URLs for evidence drawn from multiple pages. Store an excerpt privately where permissible. Record deterministic transforms by name/version with input references (e.g. UTC conversion). An excerpt containing the right words still has to describe this entity and field. Any unsupported required field goes to quarantine with a reason. Optional fields can be null. Zero, empty, false and unknown mean different things.

Use distinct fixture and live databases/schemas, evidence directories and run manifests. Admission to public export requires live provenance through every parent observation. Run IDs, mode, immutable raw hashes and source classes propagate through joins. Never let mock inputs be promoted by setting a flag on the final row. Audit the lineage recursively. Validate URL scheme and original attribution and record last observed status. Evidence copied from a public dump retains its exact dump revision and record key as well as its originating entity URL.

Extract and store full text internally only where permitted. Test completeness using source-specific article boundaries, first/last known body paragraphs, paragraph order, boilerplate rejection and paywall/truncation indicators. When public reproduction is permitted expose the full body in bounded cells, with continuation columns or an accessible artifact link as needed. Otherwise expose source URL, permitted excerpt if available, body hash, length and extraction status and disclose the public-text limitation. Reject a summary-only fetch for the full-text requirement. Choose alternate sources where permitted access or coverage is insufficient. Preflight Sheet dimensions, long text, formulas and viewer permissions.

## Time and freshness

Freeze run cutoff T in UTC, also capture observation time F per fetch. A final signal must have plausible publication time in the closed interval [T−24h,T], including at either endpoint. Archive the monitoring run and perform a new export-time filter. If collection continued past T, let a later release window capture newer items. Persist raw date, source timezone, evidence, interval lower/upper and precision. Prefer original structured datePublished/datePosted, source-native original publication field, corroborated feed published time, then labeled visible publication time. updated, lastmod, collectedAt, cache time and first_seen cannot prove publication. Check field meaning on each adapter. Conflicting primary evidence → quarantine unless a documented source-specific precedence explains it.

For “2 hours ago” displayed by a source that floors hours at F, use the conservative interval [F−3h,F−2h]. For date-only use the full day in the documented source timezone, bounded by observation only if publication by F is established. Unknown timezone, unclear rounding, daylight-saving ambiguity or relative strings from cached pages with no reliable reference need wider bounds or quarantine. Admit only if *all* plausible times fall inside the window. Store interval bounds beside the normalized date. If the exact instant is unavailable, label the exported date as a bounded estimate with precision, or omit the row from strict exact-time exports. “New since last run” = appeared between complete snapshots or first seen with changed source sequence. Queue those candidates for timestamp corroboration; mark them observed-only until proven. Never convert a quiet board into a positive count by widening the window.

## State and interfaces

Use Python 3.11+, async HTTPX, Pydantic v2, feedparser, an HTML article extractor with per-source fixtures, PostgreSQL locally and at scale (Compose or existing local service), psycopg 3 with bounded pool, pytest/pytest-asyncio, Hypothesis where generative tests add coverage. Pin compatible resolved versions and commit the lockfile in B0. Use a local Python virtual environment. Optional Playwright async for permitted JS rendering, and local Ollama if supported on the machine. Keep one CLI and one deployable worker image/process type with stage selectors. Avoid standing up a broker, vector database or orchestration cluster during the trial.

| Boundary | Contract |
| --- | --- |
| discover(source, checkpoint) | Asynchronous stream of external IDs/URLs and durable cursors. Persist discovered tasks and checkpoint atomically in page-size batches. |
| fetch(task, policy) | Raw observation or typed outcome (retry_at, denied, not_found, invalid). Share HTTP pool, streaming limits and host budgets across adapters. |
| parse(raw) | Candidate fields + evidence pointers, never invented defaults. Define separate HTML, JSON, Atom/RSS adapters. |
| extract(candidate, budget) | Validated fields and per-field evidence, or abstention. Deterministic source data can bypass inference. All unstructured records requiring inference use this path. |
| resolve(candidate) | Stable identity or auditable abstention with candidate set and rule version. |
| persist / export | Atomically write canonical row, evidence links, metrics and task completion. Export from a consistent read snapshot and stable sort order. |

Tables: runs, source_checkpoints, tasks, observations, candidates, entities, source_identities, relationships, field_evidence, repo_metrics, resolution_events, quarantines, provider_budgets. Put immutable raw bodies in a compressed content-addressed local store; configure a shared raw-store root visible to every worker (a mounted volume suffices for the trial). Persist a relative content key and checksum, then resolve it from the configured root in each process. Use unique constraints on semantic task keys (include stage/version/observation revision when reprocessing), stable entities, relation keys and metric snapshot keys. Use bounded DB indexes on ready tasks by source/stage/next_attempt, canonical identities and publication time. Filter/index AI scope, timestamps and status before export.

Workers claim ready tasks in short transactions using FOR UPDATE SKIP LOCKED, set expiring leases with fencing tokens, then release locks before HTTP/model I/O. Renew or release leases with owner and token validation. A stale worker cannot commit after another worker takes its lease. Write accepted outputs, next-stage tasks and completion together. Handle a crash between raw blob creation and database commit by reusing the content hash and cleaning unreferenced blobs later. Replay may repeat an external request; unique keys and guarded transactions provide one committed result per logical effect. Share per-host and per-provider reservations through PostgreSQL so adding workers cannot multiply a quota. Terminal failures have a reason and a deliberate requeue path. See PostgreSQL’s queue semantics. [PostgreSQL SELECT](https://www.postgresql.org/docs/current/sql-select.html)

Explicitly choose relational edges (organization OWNS product, paper IMPLEMENTED_BY repository) and indexed joins in the trial. Describe optional pgvector for candidate recall or Neo4j for measured multi-hop graph query needs. Exact identity and metric history stay in PostgreSQL. A second storage service would add synchronization and recovery work. Include migration criteria and consistency implications on page three of the PDF.
