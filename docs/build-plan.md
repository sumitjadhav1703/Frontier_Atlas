# AI Signal · implementation runbook

**Critical path.** Deliver 3,000 traceable bulk records, ten monitored sources, a real resilient LLM extraction path, deterministic mapping and reproducible output. Start with a small crawler you can replay. Build model calls and failure recovery on known inputs. Validate the entire pipeline offline before spending the first provider request. Production readiness here means predictable behavior on failure, measured limits and a recovery path. No finite suite can establish that every future source change will work.

| B5 | Provider fallback and quota governance | Deterministic failure transcripts and a hard zero-spend default |
| B6 | Startup/product resolution | Gold pairs, abstentions and stable mapping log |
| B7 | Whole-pipeline replay, export and scale measurements | Six local tabs, duplicate-free rerun, measured baseline |
| B8 | Real source and free-provider qualification followed by bulk run | Live manifests, model traces, counts and source health |
| B9 | Final freshness refresh, audit and submission packet | Fresh release snapshot, public viewer check, repo and ≤3-page PDF |

B0–B7 pass on controlled inputs. B8–B9 validate claims about the outside world. Advancing from B1 confirms the crawler’s transport and state invariants; a source layout discovered in B8 can still reopen B2. Use one scoped work order and an independent review per block. The startup line in cursor.md queues the work orders in advance. Run the project interpreter’s `python tools/gate.py Bn` at each close. The runner invokes all gate suites through Bn and all normal tests. It rejects skipped, failed and empty required suites. Tests at B8–B9 inspect captured real artifacts. Re-running tests must never publish, invoke a provider or mutate live data.

### B0 · Reproducible start and data boundaries

Build the CLI shell, project setup, frozen clock/config interfaces and minimal storage schema from contracts.md. Require an explicit live mode and a separate live database/namespace. Reject mode/DSN mix-ups. With network disabled and zero external credentials, load a five-record fixture and create a temporary test DB. Set up a socket guard that permits only explicitly needed loopback DB/test servers; block accidental public DNS/HTTP. Create a dated source-qualification inventory from sources.md. Dependency installation and fetching a container image, if needed, are bootstrap downloads and do not count as provider calls. Start a local Git repo if desired for change tracking; credentials and a remote are unnecessary.

Gate: fresh-env install and documented one-command tests; schema rejects missing required values, wrong case, invalid enum, negative stars, naive datetime and Boolean-as-int; optional employee count null round-trips. Demonstrate rejected fixture lineage and a network attempt blocked by default. Record interpreter, lockfile, DB version and bootstrap steps. No crawler behavior claimed here.

### B1 · Crawler, backpressure and recovery

Build discovery→queue→fetch→observation using pooled async HTTP and short DB transactions. Enforce global active-request and bounded pending-queue limits, per-origin concurrency/pace and maximum compressed/decoded body sizes. Set connect/read/overall timeouts; cancel cleanly. Respect robots and partner policy, validate HTTPS/public destinations and redirects, strip auth on cross-origin changes, reject unsafe or private destinations including after redirects; allow loopback only through isolated fixture transport. Normalize scheme/host, fragment and documented tracking parameters; preserve identity-bearing query values. Keep next cursors opaque; handle cycles, relative links and empty terminal pages. Implement bounded retries only for transient errors; release worker slots while delayed. Save successful raw observations before parsing. A challenge, including a 200 HTML interstitial, routes to a documented alternative or terminal blocked state. On permitted JS-only pages use bounded Playwright pool and a content readiness selector with deadline. Rendering may be documented under Phase V if dependency setup threatens delivery; ordinary async crawl stays required.

Gate: local server with redirect loop, 304 with/without cached body, timeout, 429 then success, repeated 503, permanent 404, robots denial, redirect to disallowed destination, truncated gzip, unexpected MIME, duplicate link, oversized response and challenge-as-200. Two workers contend for one task. Kill the first after fetch but before commit, restart and assert one committed effect, restored cursor, bounded attempts, stale lease rejection and no lost successors. Measure observed maximum in-flight requests under slow consumers. Verify an allowed alternate-feed fixture preserves source lineage. Network and provider calls outside localhost = 0.

### B2 · Bulk directories and paper metrics

Implement a streaming bulk adapter and concrete field maps for YC, vendor products, the paper/repo archive, arXiv and GitHub. Test each through the same queue as B1. Seed from labeled minimal fixtures modeled on published upstream shapes; label hand-authored fixtures synthetic. At B8 capture permitted real examples and replay them to catch drift. Source relations are first-class observations. Use an explicit AI inclusion rule. Prefer an author-declared repo or evidenced official association. Reject ambiguous multi-repo ties and framework/dependency repos absent primary implementation evidence. Bind each bulk checkpoint to source revision or snapshot hash and partition. On changed input, safely replay the partition with stable identity keys. Test a record inserted before a saved offset and a truncated replacement page. Preserve the versionless paper ID and v1 publication date. Deduplicate repo requests by stable repo ID/normalized URL; refresh metrics once per configured snapshot interval, e.g. 24 h before export. 304 can revalidate a cached count. A new snapshot can legitimately have fewer stars.

Gate: repeated pages and aliases, missing employee count, two products by one owner, three plans for one product, missing ownership, free trial vs freemium, renamed repo, true zero, private/deleted repo, versions of the same paper, unrelated dependency and two papers sharing one repo. Require title, authors and original publication evidence. Test string/field drift, no-code papers and dead links enter quarantine or pending queues. Replay yields one row per logical identity and stable evidence. Count eligible papers only after the metric join.

### B3 · Fresh signals and full text

Implement feed/list discovery and detail extraction, monitoring checkpoints and a per-source run ledger for the ten sources. Persist pagination completeness, scan bounds and any limitation (e.g. capped feed). Use clean article paragraphs or complete job description, include evidence of both start and end of body. Extract date intervals and source timezone using contracts.md. Keep the first-seen heuristic available for discovery and prioritization. Match original employer posting across boards, preserve each observation and original publication evidence. Do not stop scanning an unordered feed at the first old row. For ordered feeds confirm descending publication order before early cutoff; refresh with overlap to catch reordering.

Gate: freeze UTC clock; check exactly T, T−24h, 1 second older, future, timezone offsets, ambiguous DST, date-only at midnight, relative “23 hours ago” straddling cutoff, “yesterday”, missing tags, republished old article with fresh modified date, conflicts and first seen old item. Cover teaser, truncated RSS, missing last paragraph, full HTML body with a sidebar, same listing on two boards, rerun at T+2h and a legitimate empty scan. Each configured source has a parser/contract test; distinguish healthy/no eligible signals, partial, rate-limited and failed. Retain every proven-fresh eligible item.

### B4 · Grounded LLM contract and chunk planner

Use a fake provider implementing the same async interface as the live adapters. Take a real parsing path from HTML to labeled segments/JSON-LD with stable segment IDs and field-specific evidence requirements. Strip nav/scripts/boilerplate except explicitly parsed structured metadata. Instruct the model to return typed fields, quoted text, source segment IDs and null for absent values. Treat page instructions as content. Require Pydantic validation, quote location in the correct retained segment and deterministic domain predicates for names, owner, price, remote eligibility, URLs and dates. Raw timestamps, GitHub metrics and authoritative structured fields are finalized by deterministic parsers; a model cannot overwrite them. Duplicate conflicting values → review. Cache by raw hash, segments, provider/model, prompt/schema and extraction-policy versions.

Compute allowable input = context − reserved output − instructions/schema/framing − safety margin. Apply provider input-per-request cap and transport byte cap to the actual fully serialized request as additional constraints. Include tool/schema overhead once. Split by semantic sections then paragraphs, preserving evidence offsets and overlap. Split oversized individual blocks on safe boundaries. Prioritize title, date, pricing, owner and code sections. Recount the final payload per provider on each fallback. If fixed overhead cannot fit, disable that route for this item. A provider may change undocumented limits: on unexpected 413 or context-length 400 re-budget and split smaller with a strict maximum depth and minimum chunk size. A single retry of unchanged oversized bytes fails the gate. Merge field evidence deterministically, preserve contradictions and record discarded coverage.

Gate: fake transport asserts measured serialized bytes and input/output budget on every outgoing request. Cover long Unicode, emoji, code block, very long single token-like text, JSON escaping, oversized schema, lost late-page pricing and multi-chunk conflict. Golden cases include misleading same-page number, hallucinated author/price, injection text, correct quote for the wrong entity and malformed JSON. Verify abstention on unsupported data. A source-backed positive and a plausible ungrounded negative must pass through the same extractor.

### B5 · Provider adapters, fallback and zero-spend control

Implement Gemini → Groq → optionally local Ollama with per-provider request serialization and validators. Use the same interface as B4; mock only the network boundary. Select actual model IDs at B8; absent credentials disable a tier. Parse rate-limit headers, respect Retry-After (seconds or HTTP-date) and provider reset windows. For transient failure without server guidance use full jitter in [0, min(cap, base × 2^attempt)]. If server delay exceeds the local retry budget, persist next_attempt at the required time or route to another eligible provider. Never shorten a server cooldown. Separate credential/config 401/403 from quota 403, retryable 5xx/timeouts, quota 429, 413 and invalid output. Retry invalid output once within budget or abstain/fallback. Bound total attempts and wall-clock time **across** providers/chunks. Prevent thundering herds with durable shared cooldown, circuit breaker and one half-open probe. Deduplicate concurrent identical work. Capture attempts, latency, model, token usage and final evidence origin; redact payloads in public transcripts.

Budget policy: paid spend cap = 0, billing-enabled unknown plans disabled, per-run request/token caps and daily limits set from actual console. Reserve capacity before dispatch for all workers including retries, repairs and probes. Keep ambiguous/timeout usage reserved conservatively. Enforce final denial when capacity is exhausted. Queue or use local inference when appropriate. Replay/fake mode cannot qualify as a live provider. If none succeeds, abstain; structured source values with independent provenance may still be used, tagged accordingly.

Gate: table-driven scripted failures including Gemini 429 → Groq success; oversize → smaller request; context error on second provider; invalid JSON → unsupported claim → abstain; missing key; permanent 401; endless 429; all circuits open; reset and half-open success; concurrent quota race with one slot; cancelled in-flight request; cache hit making zero calls. Inject clock/RNG to test delay bounds without sleeping. Save a readable transcript and demonstrate no live calls or paid fallback.

### B6 · Deterministic entity resolution

Exercise the seed-register format and collision rules offline using 50 labeled fixture identities with stable IDs and explicit aliases. At B8 select 50 distinct startups from the already-acquired live observations to seed the live register. Reuse their original URLs and add aliases only where evidenced. This avoids a separate seed crawl. Store its revision. Test that live resolution rejects fixture seed IDs and aliases. Resolve startups and products in separate namespaces. Apply Unicode normalization, case folding, whitespace/punctuation handling and locale-aware legal suffix stripping to a *comparison key*. Match trusted source IDs/domains with ownership evidence, then unique approved aliases and collision-free normalized names with appropriate corroboration. Domains can host multiple companies; common names/acronyms and collisions must abstain. Fuzzy similarity may propose review candidates only. Persist trusted, previously unseen organizations with a new stable source-backed ID. Group product aliases only within their owner. A corporate rename with verified continuity preserves ID and event history.

Gate: OpenAI / OpenAI, Inc. / Open AI → OpenAI; punctuation/case, non-Latin names, shared hosts, homonyms, AI vs A.I. collisions, subsidiary/parent, exact product names under different owners, ambiguous alias, replays, seed-order changes, unknown organizations. Use a labeled holdout with hard negatives independent of the seed aliases. Report TP/FP/FN, precision, recall, abstention and sample size. Require zero false merges on the curated negative set; publish measured recall with denominator, investigate every missed required alias. Produce idempotent raw→canonical events and link each to its observation.

### B7 · Integrated offline replay, exports and load

Connect actual stages through CLI. Replay a mixed corpus with at least one accepted and one rejected item per applicable vertical. Start two worker processes with separate temporary working directories, the same PostgreSQL database and a configurable shared raw store (a mounted directory suffices). Prove the second process can reopen an observation created by the first using only its persisted reference. Kill/restart mid-run, rerun the same input, then replay one changed observation. Compare record IDs, counts, lineage, metric history and six tab outputs, ignoring only documented run metadata differences. Produce a fixture-mode local export in a segregated directory, visibly labeled. Add production exporter contract tests using a mock Sheets transport. Use batched deterministic fixed ranges, stable sort order, idempotent retry, RAW strings for formula-like values and a snapshot manifest. Use fresh staging workbook/new snapshot or replace previous tab contents including stale trailing rows. CSV import fallback needs spreadsheet-formula escaping and quoted Unicode/newlines. Test public field projection, long cells, partial write, read-back count/hash and absence of secrets. No fixtures may satisfy live export gates.

Benchmark synthetic 1k then 10k input candidates with 1 and 4 workers on the same machine. Record machine/DB settings, wall time, committed rows/s, p95 fetch/processing time, peak memory, queue depth, duplicate commits, retries, recovery time and a measured bottleneck. Use generated inputs lazily. Report synthetic results separately from live throughput. If resources permit, stream 500k synthetic keys as an optional stress run; never label that a 500k web scrape. For projection: time ≥ maximum of each stage’s work ÷ effective throughput, upstream rate-governed request time and provider token time; include cold start, rejection yield and retries. Size raw storage using measured compressed bytes/item × candidates, plus indexes and retention. More workers help until the source/provider limit dominates.

Gate: exact six tab names, fixtures isolated, cross-stage retries preserve logical identity, bounded working set, full-text provenance and no repeated committed effect. Save benchmark and a reviewer-ready replay command, start README and three-page design draft with clearly marked measurements pending live evidence. Keep test workloads cheap on cumulative runs by verifying saved benchmark output and a small regression case.

### B8 · Live pilot, free LLM canary and full acquisition

Start the ten monitor probes, bulk-source pilots and provider qualification independently so a missing model key cannot stall data collection. When a route qualifies, persist observations immediately. Keep publication closed until the joint gate passes.

1. Configure isolated live DB and actual free credentials; capture tier, per-model caps, remaining requests/tokens and time budget without exposing secrets. Run one permitted discovery and detail pair per signal source, a 30-item pilot per bulk class and one distinct repo check. Qualify actual field semantics, restrictions, page shapes, pagination, original URLs and rights. Capture a permitted real response per adapter and replay it against its B2/B3 parser. Qualify 50 live seed identities before final live resolution. Record real failures. Replace an unavailable source and repeat the same qualification.
2. Start with a suggested ceiling of ten remote generation attempts total including retries for the canary, subject to lower account limits. Use a few previously unseen public texts, including a missing field, and hand-label expected values before inspecting output. Demonstrate actual model-produced schema and evidence. Show success on both configured free providers where accessible, one forced local/test-boundary primary-unavailable path reaching a real alternate, and clearly differentiate simulated failure, observed HTTP error and real model response. No need to induce a live rate-limit event. If hardware and accounts leave only one usable provider, disclose partial live coverage and preserve offline fallback proof. Verify costs in provider usage or report unknown where unsupported.
3. Recalculate budget: distinct candidates needed ≈ remaining accepted target / measured unique-complete yield. For example 65% yields about 1,539 candidates for 1,000 accepted, before a reserve. Use per-stage candidate and dedup yield; do not multiply overlapping deficits twice. Estimate finish time, store it in the ledger and prioritize products and GitHub star enrichment if constrained. Start independent acquisition workers together while respecting shared limits. Use bulk snapshots for structured fields and reserve LLM calls for unstructured fields. Do not claim the LLM processed deterministic rows. Cache by versions and run frequent check-ins on counts.
4. Run monitoring at a source-appropriate interval with overlap and bounded backfill. Qualify all five boards and five publishers. Continue bulk partitions until ≥1,000 accepted unique rows in each class. Refill failed joins. If quotas run out, retain checkpoints, resume at reset or use already-qualified alternate sources. If a mandatory target remains short, record exact counts and cause; the release gate stays open.
5. Audit all rows programmatically for URL, live lineage, required fields, identity, metric timestamp and time evidence. Manually inspect a deterministic random sample (suggest 20 per bulk class, plus all signals up to 20 per class and flagged cases), verify field meaning against source, count errors and store seed and sampled IDs. A material defect reopens its parser, reruns affected records and repeats the audit.

Gate: `tests/gates/test_b8.py` reads the current real manifest/data, verifies the three 1,000 minima independently after filtering/dedup, ten qualified successful monitors, actual LLM use with traceable evidence, run mode/quotas and audit sample. Require a redacted trace from real unstructured source text through an actual provider, accepted field evidence, canonical entity ID and a row in the live export projection. Prefer a product row for this demonstration because a fresh signal may age out before release. Retain the B8 trace as historical evidence. Record per-vertical counts for structured-only and LLM-assisted records, plus unsupported-field abstentions. A detached provider demo cannot satisfy this test. Recompute predicates from rows and lineage; a hand-entered total cannot pass. If capture is inaccessible or all LLM evidence is fake, remain BLOCKED. A successful monitor may find zero fresh signals. Record rejection counts and last success for every source. Export later using a new final cutoff.

Include no API keys or private raw data. Document commands, coverage by source, run ID, measurements, limitations and sample evidence in README. Provide commit/tag and Sheet link, with publish actions performed by the applicant unless specifically authorized.

**Architecture PDF, at most 3 pages.** Page 1: pipeline topology, source adapters, queues, bounded workers and **measured** 500k projection (explain scope if 500k per class). Page 2: exact byte/token arithmetic and fallback states incl. 413/429, example trace, hard limits and circuit behavior. Include a short Phase V case in README: name one high-value source, show the observed block or clearly labeled fixture, the permitted alternate route, a sample traced record where available and any coverage lost. A simple reviewer demo: follow one Sheet row to its evidence, show an unsupported row in quarantine, replay a rate-limit fallback and restart a worker without changing output counts.

Gate: a release manifest binds export cutoff, source/row counts, workbook ID, repo revision, PDF digest/page count, two clean viewer checks and clean-clone replay. Validate six actual tabs, ≥1,000 rows per bulk class, complete fresh window and traceability. From the frozen source-observation snapshot independently compute the eligible deduplicated news/job IDs. Compare expected IDs with IDs read back from each public tab in both directions, and separately reject duplicate IDs. Trace at least one actual released model-assisted row to its own real model output, evidence and field values. Reuse the B8 example if still eligible, or use another eligible traced row. Test a B8 job aging out while a different grounded row supplies the release proof. Report proven-fresh items missing required fields as unresolved with reason and count; reconcile them before claiming complete coverage. Require one complete, successful scan per monitored source covering the release window, with watermark, pagination termination and pending/rejection counts. A capped feed with no proved overlap is partial. Inject one omitted eligible row, one extra stale row and one repeated ID into copies of the export, and verify each fails. Keep all six tab headers when an eligible set is empty. Applicant opens the form and submits the verified links before the deadline; keep the form receipt separately.
